# 扩展开关 —— 设计取舍与验证记录

2026-09-26

## 要解决的问题

浏览器的扩展管理页要开标签页、滚动、点两下才到位，而「临时关掉某几个扩展」是高频动作
（排查冲突、看视频时关掉广告拦截、跑测试时关掉脚本注入）。所以需求是：**点一下工具栏图标，
立刻开关**。

约束来自浏览器本身：能读改别的扩展状态的只有 `chrome.management` 一个 API，它要求的
`management` 权限装的时候必然弹一条「管理您的应用、扩展程序和主题」。这条绕不过去，
也没有更窄的替代，就接受它，在 README 里明说。

## 形态：只有一个小弹窗

选定的交互是「点图标 → 300px 小面板 → 开关 + 搜索 + 底部三个批量按钮」。**没有**后台脚本、
内容脚本、选项页——面板打开时读一次 `getAll()`，关掉什么都不剩。

按「简约」砍掉的三样，都是明确权衡不是遗漏：

| 砍掉的 | 为什么 |
| --- | --- |
| 用户自定义分组 / 预设组 | 会把面板加厚一层标签页，而「全部关」+ 逐条点已经覆盖大多数场景 |
| 键盘快捷键 | 面板存活几秒，省下的那一次点击抵不上多一条 `commands` 配置 |
| 独立标签页大面板 | 卡片网格信息全，但每次开关要多开一个标签页，跟「快速」直接冲突 |

## 界面方向：单色的精密感

这是每天开十几次的工具面板，正确做法是克制而不是抢眼。

- **开关不用蓝绿**。亮色模式「开」= 墨黑 `#1b1b1a`，深色模式反相成近白 `#ededeb`；
  唯一的颜色（`--focus` 蓝）留给焦点环和错误提示。换来一条能用的视觉线索：开着的行
  名字是正常墨色，关掉的压暗一档，整列扫下来就知道哪些在跑。
- **不打包 web font**，用系统 UI 栈（`Segoe UI Variable Text` → `Microsoft YaHei UI`）。
  面板每次打开都要等字体文件，为一个工具面板不值得。Windows 11 原生手感本来就是目标。
- 开关是自己画的（`<button role="switch">` + `::after` 做滑块），不是一个 checkbox 改样式：
  角色、键盘、无障碍语义都白拿，滑块动画也能精确控制。
- **整行都可点**，不是只有右边的开关。开关只有 30×18，行有 288×38——后者不用瞄准，
  快得多，而且面板视觉上一点没变厚。点击挂在行上、开关自己的点击冒泡上来走同一条，
  所以不会翻两次（`test/check.mjs` 里专门有一条断言这个）。光标跟着改成 pointer，
  不然热区比看起来大，属于骗人。

## 架构：三个状态来源要分清

面板自己记的状态（`items`）／`storage.session` 里的撤销快照／`chrome.management` 的真实状态。
平时以 `items` 为准——`setEnabled()` resolve 之后立刻 `getAll()` **不保证**已经反映新值，
所以点开关是「先动界面、失败再翻回来」，而不是等真实状态回来才动（那样手感是黏的）。
只有「别处也改了扩展」时才去对齐真实状态，靠 `onEnabled` / `onDisabled` 两个监听。

撤销快照放 `storage.session` 而不是 `local`：面板一关内存就没了，而撤销经常发生在
关掉再打开之后；`session` 的寿命（到浏览器重启为止）正好是撤销窗该有的长度。

批量操作之前先存快照，逐条操作不存——所以「撤销」的语义是**退掉上一次批量操作**。
逐条开关要退回来就再点一下那个开关，比给每条操作都维护一个撤销栈简单得多，也够用。
快照在撤销后被清掉，按钮变灰，含义单一。

已经全关时再点「全部关」不建快照（否则会留下一个点了没反应的死按钮），如实提示
「已经全部关闭」。

## 两处实测得出的事实

**一、别的扩展的图标能直接 `<img>` 加载。** 本来担心 MV3 的 `web_accessible_resources`
会挡住跨扩展的资源加载，所以代码里铺了两条路：优先 `<img>`，`onerror` 时换成按名字取
首字的字符瓦片。实测（Chrome 153 无头 + 4 个假扩展）带图标的那个 `naturalWidth > 0`，
`<img>` 这条路通。瓦片因此只是兜底，不是主路径——如果当初按「应该会被挡」直接做瓦片，
就会白丢掉真实图标。

**二、中文排序是拼音序。** `localeCompare(name, 'zh-Hans-CN')` 下实测：中文名按拼音排在
前面（沉浸 → 屏幕 → 网页 对应 chen/ping/wang），拉丁名 A–Z 在后，希腊字母垫底。这跟
浏览器自己的中文排序一致，所以位置能形成肌肉记忆。

## 验证

`node test/check.mjs` 10 条场景，连跑三轮全过。每条都是独立的无头 Chrome（全新临时 profile），
场景间不污染。

覆盖：列表构成与排序、图标两条路、全部关、撤销、点开关、点整行（且只翻一次）、撤销快照跨
「关掉面板再打开」、重复点全部关、搜索命中/未命中、空面板文案。

**最要紧的一条断言是 `mismatched === 0`**：界面上的开关状态跟 `chrome.management` 报的
真实状态必须一致。只看界面会假通过——UI 翻了、扩展其实没被停用，是最容易漏的失败。

另外量过（14 行、列表溢出滚动时）：`scrollH 542 > clientH 480`，开关右边缘离列表内容区
右边缘还有 7px，滚动条不压开关。这个数必须把滚动条自己占的 8px 减掉才算得准——按边框盒
量会多出 8px，真压上了也看不出来。

### 查过的一个假失败

连跑时偶发 `exit 1`，而且**每次失败的场景都不一样**，dump 内容却全对——这种"内容对、
退出码不对"的形状说明问题不在断言，在进程本身。驱动本来把 `[fatal]` 打在 stdout 上，
而 `check.mjs` 的 catch 只读了 stderr，等于把死因吞了；补上 stdout 之后真因立刻现形：
`CDP 端口没起来`。

端口原先是 `9310 + pid % 380`（沿用 hover-zoom 的做法，用来避开固定端口的坑）。但
`check.mjs` 是一条接一条起 Chrome，pid 会被复用，算出来的端口照样撞上一个还没退干净的
实例。改成向系统要一个空闲端口（`listen(0)` 拿号再放掉），三轮连跑不再复现。顺带把
`cleanup` 做成只执行一次——重复 `process.exit` 会把 0 盖成 1。

调试产物（截图、图标对照图）用完已删，`.gitignore` 挡住重新生成的。

### 没验到的

- **真实浏览器 profile 里没跑过。** 无头用的是临时 profile，装扩展会改状态，不能拿真
  profile 做自动化。所以「用户在 Edge 里装了 11 个扩展时的实际观感」是按 14 个假扩展的
  场景推的，没在真环境确认。
- **`mayDisable === false` 那条分支没实测。** 临时 profile 里没有内置扩展，`skipped`
  一直是空串。那段的提示排版是注入 DOM 模拟后截图看的，计数逻辑（`if (!e.mayDisable) locked++`）
  本身没有真实输入验过。真实 profile 里大概率会命中这条分支（组件扩展），第一次打开面板
  时值得看一眼底部那行。
- **`setEnabled` 的失败分支没实测。** 触发它需要一个装不掉的扩展，临时 profile 里造不出来；
  代码路径是「翻回开关 + 弹错误提示」。

### 一个意外发现（顺带印证了一件事）

测试跑到一半，列表里凭空多出一个 **IDM Integration Module**——那是本机真装的 IDM 扩展。
Chrome 会从注册表把外部扩展装进**每一个**新 profile，并且安装态就是 disabled（等用户确认）。
所以「扩展会在运行中冒出来」是真的，只是它没被「全部关」波及（批量那一刻它还不存在），
撤销也只还原快照里的成员，行为正确。

（2026-10-01 把它的落点量准了，以及它为什么会让断言随机挂 —— 见下面那节。）

## 2026-10-01：开着的默认排前面 + 重排动画

两个新需求：默认把开着的扩展排到前面；开关时那一行从原位置滑到新位置，并且排序方式可配。

### 排序：三种，存在 local

| 方式 | 顺序 |
| --- | --- |
| 开着的排前面（默认） | 开着的在前、关掉的在后，各组内按 `zh-Hans-CN` |
| 按名称 | 全部混在一起按拼音 —— 就是原来的行为 |
| 最近开启的排前面 | 开着的在前，其中"被这个面板打开过的"按时刻倒序，其余开着的按名字；关掉的按名字垫底 |

**「最近开启」的时刻语义**（本次唯一新增的状态）：面板把它打开时记下 `Date.now()`，关掉时把
时刻作废（关着的没有"最近开启"可言）。撤销走快照，所以快照从 `{id,on}` 扩成 `{id,on,onAt}`，
撤销之后顺序一并还原。在 `chrome://extensions` 里手动开的**不记**——那会儿面板没在跑，
无从知道时刻，它们按名字排在"有时刻的"后面。存在 `storage.local`（该跟浏览器同寿，不像撤销
快照只活一会儿），面板每次打开顺手裁掉已卸载/已关掉的条目，不然这张表只涨不消。

不给时刻设过期时间是刻意的：它是"上次被打开"的排序键，不是"最近用过"的统计口径。浏览器重启后
仍然开着的那些，时刻依然是真的，排出来的顺序也依然符合直觉；加一个 30 天过期只会让列表
在某个早晨莫名其妙换一种排法。

### 动画：FLIP，一条路径管住所有会改位置的操作

改顺序**前**量一次每行的位置 → 改 DOM → 再量一次 → 用两次之差做一次位移动画。
第一段量的是"眼睛现在看到的位置"（行正在滑时 `getBoundingClientRect()` 把 transform 一起算了
进去），所以连点两下能接着滑，不会先跳回起点。

被点的那一行是"被拎起来放过去"，分三段走完 400ms：

| 段 | 时间轴 | 干什么 |
| --- | --- | --- |
| 浮起来 | 0 → 0.22 | 放大到 1.04、往上升 4px、淡影渐显。**升的方向永远是上**，跟它要往哪走无关 |
| 飞过去 | 0.22 → 0.7 | 就浮着横越到新位置（末尾比目标位置还高 4px） |
| 降下去 | 0.7 → 1 | 落回原尺寸、影子收掉，停在原地 |

段间缓动接成一整条 S 曲线（浮起来 ease-out → 飞过去 ease-in → 降下去 ease-out），
所以看起来是一次"拎起—搬运—放下"，不是三段拼接。

初版是 220ms 直接滑过去，太快：看不出动的是哪一个，也没有"被拎起来"的质感。

| 决定 | 为什么 |
| --- | --- |
| 用 Web Animations API，不给元素挂 transition 类 | 动画自己会结束、不残留内联样式。反过来它也躲得开 CSS——`prefers-reduced-motion` 那段 `animation: none` 拦不住它，所以必须自己判一次 `matchMedia` |
| **只有被点的那一行**浮起来（底色 + 淡影 + 抬到最上层），让位的行什么都不加 | 全加过：一片行同时变成长着投影的卡片、还互相盖来盖去，看着一团乱，反而分不清刚动的到底是哪一个 |
| 让位的行先按住不动（0→0.22），等它浮起来再一起滑 | 不然被点的那个刚离地，其余的先动完了，像两件事 |
| 影子跟着关键帧收放，不写在 CSS 类里 | 它得配合"浮起来/降下去"一起变。`--lift` 是 CSS 变量、要从 JS 读出来塞进关键帧（关键帧里写 `var()` 能不能解析不赌了，读计算值最稳） |
| 批量操作一条一条改状态、最后只重排一次 | 逐条重排的话中间那些状态会来回横跳 |
| 只滑，不滚 | 见下 |

**批量操作没有"被点的那一行"**，所以整片平着滑，谁也不浮起来——这是有断言守着的。

**不做自动滚动**：列表滚下去之后把一行打开、它飞到顶部离屏了，面板不跟着滚。要正确就得先算
目标位置再滚，多一层两阶段计算；而列表最高 480px，顶部那组多数还在视野里，不值这个复杂度。

### 配置入口：底栏第四格 + 小菜单

底栏从 3 格变 4 格（全部关 / 全部开 / 撤销 / 排序），点「排序」在它上方弹出一列，三项、当前项
打勾。打勾用两条边框转 45° 画，不用 `✓` 这个字符——字形在系统字体里不一定有，缺了就是白方块，
而且缺字形不会有任何报错。

点菜单外面时要把这一下**吃掉**（捕获阶段 `stopPropagation`）：不然它会继续传下去，正落在某一行
上，顺手把人家的开关翻了。这条有专门的场景守着。

菜单浮在列表之上，行数少时（4 个扩展 → 面板总共才 241px 高）会盖住靠下的那几行。这是下拉菜单
的正常形态，不做特殊处理；被盖住的那几行点不到，点它们只会关掉菜单。

### 验证

`node test/check.mjs` 从 10 条加到 18 条。新增里最要紧的是动画那两条，判据是几条一起成立：

> 第一帧的位移必须等于前后两次实测位置之差；起手位置必须是旧位置；那个动画必须真的跑完
> （被 cancel 的动画 `finished` 是 reject，进不了 finished 名单）。

只看第一条，"先瞬移、再在原地做一次 0 位移的动画"照样过；只看"`animate()` 被调用过"，
被重排 DOM 掐掉的动画也照样过——而后者恰恰是最可能出的 bug。装置是把 `Element.prototype.animate`
包一层（`--probe-anim`），记下第一帧位移、调用那一刻的实际位置、以及 `finished` 有没有 resolve。

"浮起来"那条另外逐帧采样被拎起来那一行的位置，判据是**它得先跑到起点上方去**（实测：
从 83 升到 78.3，也就是那 4px 的上抬 + 放大带来的 0.76px），最后落回新位置。只看"位移对了、
动画跑完了"是分不出"浮起来再放过去"和"直接滑过去"的。

**证伪跑过**，证明断言不是空转：

| 怎么弄坏 | 谁报错 |
| --- | --- |
| `prefersReduced()` 强制成 `true`（动画全没了） | 动画那条报"该有 3 行动，实际 0" |
| `on-first` 的比较器换成纯按名字 | 排序和动画一共 5 条 |
| 去掉浮起来那一下（`FLY_HOP = 0`、`FLY_GROW = 1`） | "没'先浮起来'（过程中最高只到 83，起点 83）" |

`--reduce-motion` 走 CDP 模拟 `prefers-reduced-motion: reduce`，不是改代码里的开关——要验的
正是"面板真的读了系统的这个设置"。

### 两个把时间白白花掉的坑，记在这儿

**一、扩展目录的根下不能有以 `_` 开头的文件。** Chrome 直接拒绝加载：

```
Cannot load extension with file or directory name _x.
Filenames starting with "_" are reserved for use by the system.
```

**只在根下**——子目录里的不管（实测：`icons/_sheet.png` 在着也能加载，而根下的 `_p.txt`、
`_falsify.mjs` 一放就挂）。`.gitignore` 里那两条 `test/_*.png` / `icons/_sheet.png` 之所以一直没
出事，正是因为它们都在子目录里。

踩到的方式很隐蔽：调试时用 `> _p.txt` 把驱动的输出转存到扩展目录里，下一次跑就报这个——
但症状是"驱动一个 `[probe]` 都不打"，看起来像探针坏了。所以临时文件别放扩展根下，
放到系统临时目录去（`--shot` 就是这么写的）。

**二、判死因要看驱动自己的 stdout。** 上面那个坑第一次出现时，我拿
`| rg -o '\[probe\]' > file` 消费输出，结果把 `[fatal]` 一起筛掉了，于是连着几轮都在猜
"是不是管道丢内容"。要机器读输出就直接 `execFileSync` 拿字符串；要在 shell 里看，
`2>&1 | tail` 能看到 `[fatal]`。

### 顺带把上次那个"意外发现"钉死了

上次记的"测试跑到一半列表里凭空多出一个 IDM"，这次量准了：

- 它是 `installType: sideload`、`mayDisable: true`、`enabled: false`，由注册表声明成"外部扩展"，
  Chrome 会把**每一个**新 profile 都装上它；
- 落地时刻是**面板页面加载后 700ms 上下**，而面板只在打开那一刻读一次列表（约 150ms）。
  于是同一次跑里，开头的 dump 是 4 行、`reload` 之后变成 5 行——环境在变，不是面板在变，
  但断言会随机挂。

想把它卸掉，两条路都堵死了：`chrome.management.uninstall` 对 sideload 扩展会挂住不返回
（实测。换 CDP 的 `userGesture` 求值也一样——大概率是弹了浏览器级确认框，无头下没人点它）；
CDP 自己的 `Extensions.uninstall` 文档里写明只支持 unpacked 装的。

所以改成让顺序类断言只比对自己那 4 个假扩展。这是取舍不是遗漏：多一行外界扩展既遮不住
"不列自己"和"界面与真实状态一致"（这两条仍然跑全表），也不改变要验的行为。代价写在测试代码的
注释里，免得下次又有人花两小时去卸它。
